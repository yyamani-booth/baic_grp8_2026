**Diagnosis, confirmed:**
- **Case 1 = Model.** The task definition and input were adequate, and the model *knows* sfogliatella has lard and ragù has beef. It still slips intermittently (3 of 4 runs) when writing a long itinerary. This is "ignores a clear instruction / incorrect conclusion" in the lab's table. *Underlying Controls gap:* nothing checks items against hard constraints before travelers see them.
- **Case 2 = Input.** Correcting only the structured profile removed the error (2 of 3 → 0 of 2). The free-text-only constraint plus the contradictory `HARD constraints: none stated` caused it.
- **Case 5 = Task definition.** Rewording only rule 1 turned "seafood dropped" into a safe optional split. The model was following our instruction.

**Takeaway for Part 3:**
- **Most costly for users:** case 1 (a hard dietary rule broken, hard for the traveler to notice: the over-reliance risk Assignment 4 calls our biggest).
- **Shows up most:** the hidden-violation pattern (cases 1, 2, 3).
- **Key insight for choosing the fix:** the model gets the facts right when asked one focused question, but not while writing 30 items. A fix that **adds a focused check step after generation** (fix menu: *Workflow and harness* / *Rules and Gating*) fits this evidence better than just adding another line to the prompt.

## Part 4: Build the fix

**Saved copy of the working version:** `~/Downloads/liaison_backup_before_fix/` (no `.env` key, no logs). To undo: copy `server.py`, `app.js`, `index.html` and `config.json` back from there.

**What changed (only what the fix needs):**
- **`server.py`:** new `CHECK_PROMPT` and `check_itinerary()`. After the itinerary is generated, a second, focused call reviews every item against each traveler's own words and profile (diet, alcohol, allergies, mobility), including hidden ingredients and real terrain. It returns only risky items with a one-line reason, which is attached to the item as a warning. Logged as `"kind": "itinerary_check"` (prompt, raw output, flags, seconds, tokens). If the check fails, the itinerary is still shown and `itinerary_check_error` is logged.
- **`app.js` + `index.html`:** a red **⚠ Check this: [traveler]: [reason]** box under each flagged item, plus a banner at the top of Step 4 ("Safety check flagged N item(s)…", or a warning if the check didn't run). The warning is cleared when an item is revised after a rejection, because the revised text hasn't been checked.
- **`config.json`:** `"check_enabled": true` (set to `false` to turn the fix off for before/after comparisons), `"check_model": ""` (empty = same model as the itinerary), `"check_max_tokens": 4000`.
- **Unchanged:** the itinerary prompt, the model, simulated mode (`?sim=1` still gives the canned plan with no check), the accept/reject flow and the log.
